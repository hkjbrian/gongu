## 0. 리뷰 사고 원칙

체크리스트는 알려진 패턴의 누락을 막는 보조 수단이다. 진짜 리뷰는 코드를 읽으며 스스로 질문을 던지는 과정이다. 아래 4가지 원칙을 기반으로 생각하면, 명시되지 않은 문제도 발견할 수 있다.

### 원칙 1 — 실행 흐름을 끝까지 추적하라

새로운 엔드포인트 또는 수정된 기능마다 요청이 들어오는 순간부터 응답이 나가는 순간까지 흐름을 확인한다.

```
HTTP Request
  → Controller (인증·입력값 검증)
    → Service (트랜잭션, 비즈니스 로직)
      → Repository (쿼리 실행)
        → DB
      ← 엔티티 or Projection
    ← DTO 변환 (어디서? 무엇을 접근?)
  ← ResponseEntity
HTTP Response
```

이 흐름에서 각 화살표(→ ←)마다 물어라:

- **이 시점에 트랜잭션이 열려 있는가?** — 없다면 Lazy 필드 접근, Dirty Checking, 롤백이 모두 동작하지 않는다
- **이 데이터는 신뢰할 수 있는가?** — 인증·권한 검증 전에 DB 조회가 먼저 일어나지는 않는가
- **루프나 스트림 내부에서 추가 쿼리가 발생하는가?** — `.map()`, `for`, `forEach` 안에서 연관 엔티티를 접근하면 N쿼리가 된다
- **반환 직전 변환 시점에 Lazy 필드에 접근하는가?** — DTO 변환 메서드 내부까지 확인한다

### 원칙 2 — 실행 시점의 컨텍스트를 상상하라

코드는 단독으로 실행되지 않는다. 아래 환경을 항상 의식하며 읽는다.

- **트랜잭션 경계**: `@Transactional`이 선언된 메서드를 벗어나는 순간 Hibernate 세션이 닫힌다. 그 이후의 Lazy 접근은 `LazyInitializationException`이다.
- **동시성**: 같은 데이터를 여러 스레드가 동시에 수정할 수 있는가? 낙관적 락(`@Version`)이 필요한가?
- **예외 시점**: 예외가 던져지면 어떤 데이터가 어떤 상태로 남는가? 롤백이 의도대로 일어나는가?
- **외부 시스템 호출 순서**: 외부 API 호출이 트랜잭션 안에 있으면, 외부 호출 성공 후 DB 롤백 시 데이터 불일치가 발생한다.

### 원칙 3 — 레이어 경계에서 계약을 검증하라

레이어 간 경계는 계약이다. 경계를 넘을 때마다 확인한다.

| 경계 | 확인할 계약 |
|------|-------------|
| Client → Controller | 입력값 검증(`@Valid`)이 이루어지는가? 인증이 요구되는가? |
| Controller → Service | Entity가 아닌 DTO를 주고받는가? |
| Service → Repository | 소프트 딜리트 조건(`deletedAtIsNull`)이 쿼리에 포함되는가? |
| Service → 외부 API | 실패 시 `InfraException`으로 감싸는가? 트랜잭션 밖에서 호출되는가? |
| Service → Controller (반환) | Entity가 노출되지 않는가? (`ResponseDTO.from(entity)` 패턴) |

### 원칙 4 — "이게 잘못되면 어떤 증상이 나타나는가?"를 물어라

각 코드 조각에 대해 최악의 시나리오를 상상한다.

- 이 메서드에 `@Transactional`이 없으면? → Dirty Checking 미동작, 롤백 안 됨
- 이 권한 체크가 없으면? → 타인의 데이터를 조회하거나 수정할 수 있음
- 이 Repository 메서드가 Lazy 연관을 포함한 컬렉션을 반환하면? → N+1 발생
- 이 예외가 잡히지 않으면? → 스택 트레이스가 클라이언트에 노출될 수 있음

## 2. 리뷰 판정 기준

| 판정 | 기준 |
|------|------|
| **APPROVE** | 모든 섹션 이상 없음 |
| **COMMENT** | Minor 이슈만 존재 (아키텍처·보안·트랜잭션 문제 없음) |
| **REQUEST_CHANGES** | Critical 이슈 존재 — 아키텍처 규칙 위반, 보안 취약점, 테스트 핵심 케이스 누락, 명백한 런타임 오류 유발 구조 |

### Critical 이슈 예시
- Entity에 public setter 또는 외부 노출 `@Builder` 존재
- `@Transactional` 없이 쓰기 작업 수행
- 권한 검사 누락 (인증 없이 타인 데이터 접근 가능)
- 핵심 비즈니스 규칙에 테스트 없음
- 실행 흐름 추적 결과 런타임 오류(LazyInitializationException, 데이터 불일치 등)가 명백히 발생하는 구조

### Minor 이슈 예시
- 변수명 개선 제안
- 불필요한 주석
- 테스트 DisplayName 불명확
- 인덱스 미활용 (성능 영향 미미한 경우)
