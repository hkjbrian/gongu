# Project Brief

## 문제 정의

점포 기반 공동 구매(공구) 운영 과정에서 상품 모집, 주문, 결제, 픽업 상태 관리가
분산되어 운영자와 사용자가 현재 상태를 명확히 파악하기 어렵다.

공급자·본사·매장·고객의 4자 이해관계가 얽혀 있음에도 이를 하나의 시스템에서
일관되게 처리하는 플랫폼이 없다.

## 목표

점포 기반 공동 구매의 상품 모집 → 주문 → 결제 → 픽업 흐름을
단일 상태 모델로 관리한다.

- 매장 관리자: 상품 등록, 주문 현황 확인, 입고 처리
- 회원: 공구 주문, 결제, 픽업 완료 처리
- 시스템: 재고 정합성 보장, 결제 검증, 상태 전이 제어

## 핵심 기술 주제

| 주제 | 설명 |
|------|------|
| 재고 동시성 제어 | 공구 오픈 시점 동시 주문 → 비관적 락으로 overselling 방지 (ADR-005) |
| 주문 상태 전이 | RESERVED → PAID → ARRIVED → RECEIVED / CANCELLED 상태 기계 |
| 트랜잭션 경계 | 재고 차감과 주문 생성을 같은 트랜잭션 안에서, 결제는 별도 처리 |
| 결제 검증 | PortOne imp_uid 기반 서버 사이드 금액 검증 및 멱등키 중복 방지 |
| 소프트 딜리트 | 회원·관리자 삭제 시 deletedAt으로 상태 보존 |

## Non-Goals

- 공급자 직접 정산 시스템
- 실시간 재고 동기화 (Redis + Kafka 아키텍처)
- 추천·큐레이션 시스템
- 실시간 채팅
- 다중 PG 지원
- 모바일 앱 (API 서버만 제공)
